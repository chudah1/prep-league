# STL Container Costs

Filled from memory first, then checked against cppreference. Cells corrected after the memory pass are **bold**.

| Container | Memory layout | Approx. per-element overhead (64-bit) | Invalidation on insert | Invalidation on erase | Insert / erase / find complexity | Cache behavior during iteration |
|---|---|---:|---|---|---|---|
| `vector` | One contiguous allocation. | **0 bytes of metadata per element; the vector object is typically three pointers (24 bytes), and unused capacity is extra storage.** | If capacity changes, all iterators and references. Otherwise, those at or after the insertion point, including `end()`. | Erased element and everything after it, including `end()`. | Back insert: amortized `O(1)`; middle/front insert: `O(n)`; back erase: `O(1)`; middle/front erase: `O(n)`; find: `O(n)`. | **Excellent: contiguous storage gives spatial locality and effective hardware prefetching.** |
| `deque` | **Chunked: a map of pointers to separately allocated fixed-size arrays.** | **No fixed metadata in each element; approximately one 8-byte map pointer per block, amortized across the block, plus unused block space.** | **End insert: all iterators invalidated, but existing references/pointers remain valid. Middle insert: all iterators and references invalidated.** | **At front, only erased elements; at back, erased elements plus `end()`; middle erase invalidates all iterators and references. References to other elements survive end erasure.** | End insert/erase: `O(1)`; middle insert/erase: `O(n)`; find: `O(n)`; indexed access: `O(1)`. | **Good within a block, but worse than `vector` across block boundaries and with an extra indirection.** |
| `list` | Separately allocated nodes in a doubly linked list. | At least 16 bytes for `prev` and `next`, plus padding and allocator overhead. | None. | **Only iterators and references to erased elements.** | Insert/erase: `O(1)` given the position; finding the position or value: `O(n)`. | Poor: pointer chasing through scattered nodes causes cache misses and limits prefetching. |
| `map` | Node-based balanced search tree, typically a red-black tree. | **At least 24 bytes for left, right, and parent pointers, plus colour/padding and allocator overhead.** | None. | Only iterators and references to erased elements. | Insert, erase, and find: `O(log n)`. | Poor: tree traversal pointer-chases through separately allocated nodes. |
| `unordered_map` | Bucket array plus separately allocated nodes, typically linked into bucket chains. | **Typically at least an 8-byte next pointer per node, plus allocator overhead and sometimes a cached hash; at load factor near 1, the bucket array adds roughly another 8 bytes per element.** | Rehash invalidates all iterators; without rehash, none. Pointers and references to elements remain valid even after rehash. | Only iterators and references to erased elements. | **Average insert, erase, and find: `O(1)`; worst case: `O(n)`.** | **Usually poor-to-mixed: the bucket array is contiguous, but accessing and iterating nodes requires pointer chasing.** |

Invalidation rules verified against cppreference: [`vector`](https://en.cppreference.com/w/cpp/container/vector), [`deque`](https://en.cppreference.com/w/cpp/container/deque), [`list`](https://en.cppreference.com/w/cpp/container/list), [`map`](https://en.cppreference.com/w/cpp/container/map), and [`unordered_map`](https://en.cppreference.com/w/cpp/container/unordered_map).
